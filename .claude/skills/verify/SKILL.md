# Verify a change

Run the script from the repo root. It takes about 1–2 minutes and leaves the generated Xcode project as it found it (free or paid build):

```sh
PlaceLock/scripts/verify.sh            # tests + paid compile + migrations if supabase/ changed
PlaceLock/scripts/verify.sh --screens  # also screenshot Home (locked and unlocked), Coves, About, the 24 h sheet, Backup, Debug, Add place and first-run setup
# Screenshots run in a scenario store with three fixed places and backup off, so nothing reaches the live Supabase project.
PlaceLock/scripts/verify.sh --large-text  # --screens, plus the same screens at the largest accessibility text size (large-*.png)
PlaceLock/scripts/verify.sh --quick    # unit tests only, for fast checks while working
```

Other flags: `--release` (also compile the paid build in Release, what ships; use it for anything touching the specs, Info.plist or `#if DEBUG` code), `--no-paid`, `--db` (always run the migration checks), `--sim "iPhone 17 Pro"` (or set `VERIFY_SIM`). If the Simulator dies before the tests start, the script restarts it and tries once more.

Run it with a 10-minute Bash timeout. Don't run two at once in the same checkout: they share the project files and `PlaceLock/build/`. Separate git worktrees are fine.

## Choosing flags

- Pure logic, rules or sync change: the default run.
- Anything under `Views/`, `Shared/Brand.swift` or user-facing text: add `--screens`, then open each PNG in `PlaceLock/build/verify/` with Read and check it shows the change. Look for clipped text, overlapping rows and wrong wording.
- A screen the default shots miss: launch it yourself with the same `xcrun simctl launch … <args>` pattern the script uses (launch arguments are in CLAUDE.md).
- Halfway through a change: `--quick`. Do a full run before calling it done.

## Reading the results

The script ends with a PASS/FAIL line per step and exits non-zero if any failed. Full logs are in `PlaceLock/build/verify/` (`test.log`, `paid.log`, `db.log`).

- On a failure, the script prints the compiler errors and the `✘` test lines. Read the log for more and fix the cause. Don't skip or loosen a test to get it passing unless the product rule it checks has deliberately changed; if it has, say so.
- Paid build fails but free passes: usually code inside `#if SCREEN_TIME` or in `Extensions/Shield` / `Shared/` (compiled into the extension too).
- If the paid project has to be regenerated by hand, run plain `xcodegen generate` afterwards unless the user is working on the paid build.

## Reporting

Report exactly what ran and what it printed: the test count from the "Test run with N tests" line, each step's PASS/FAIL, and screenshots looked at. Name any step you skipped.

If the change affects Screen Time shields, background relaunch after a force-quit, or real arrive/leave timing, the Simulator can't prove it. Add a short checklist of what to try on the iPhone.
